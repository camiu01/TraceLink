# HTTP API reference

TraceLink serves a small HTTP API from the ESP32 access point at `http://192.168.4.1`. All responses use `Cache-Control: no-store`. The API is versionless and internal to the dashboard; it is not a stable public interface.

## GET /

Returns the dashboard HTML (`text/html; charset=utf-8`), embedded in the firmware at build time.

## GET /api/systems

Returns the contents of `web/systems.json` (`application/json`): a list of device profiles. Each profile has `name`, `bus` (a source name such as `RS232`), integer `rate`, and `commands` (`name`, `encoding` = `hex`|`text`, `data`; CAN profiles may add `id`, `extended`, `rtr`, `dlc`). The file is validated at build time by `scripts/embed_web.py`.

## GET /api/events?after=<cursor>

Poll endpoint. `after` is the last sequence number already seen (decimal, up to 15 digits; anything else is HTTP 400 `invalid cursor`). Returns up to 32 events after that cursor.

```json
{
  "boot": "1a2b3c4d",
  "uptime": 12345,
  "latest": 200,
  "lost": 0,
  "overwritten": 72,
  "canReady": true,
  "canMissed": 0,
  "canOverrun": 0,
  "canErrors": 0,
  "armed": false,
  "busy": false,
  "scanning": false,
  "estimates": [9600, 0],
  "canDetected": 0,
  "message": "Pronto. Trasmissione disabilitata.",
  "interfaces": [
    {"name": "RS232", "protocol": "serial", "ready": true, "rate": 9600, "count": 120}
  ],
  "events": [
    {"seq": 73, "ms": 12000, "source": "RS232", "hex": "30 31",
     "id": 0, "ext": false, "rtr": false, "dlc": 0, "tx": false}
  ]
}
```

Field notes:

- `boot`: random per-boot token; mutating requests must send it back in the `X-TraceLink` header. A changed `boot` means the board rebooted.
- `latest` / `lost` / `overwritten`: sequence high-water mark, events skipped for this client because they were overwritten, total history overwrites.
- `canMissed` / `canOverrun` / `canErrors`: TWAI driver counters; they restart when the driver is reinstalled (speed change, scan, arm/disarm).
- `estimates`: baud estimates for RS232 and RS485 from the last scan (0 = inconclusive). `canDetected`: applied CAN rate after a successful scan.
- `message`: human-readable status from the last control operation (currently in Italian).
- `events[].source`: `RS232`, `RS485`, or `CAN`. For CAN, `id` is decimal and `ext`/`rtr`/`dlc` describe the frame. `hex` is empty for RTR frames.
- `events[].tx`: true for records generated by a user send.

## POST /api/control

Form-encoded (`application/x-www-form-urlencoded`). Requires the `X-TraceLink: <boot>` header; a missing or stale token yields HTTP 403 and the fix is reloading the page. No CORS headers are sent.

| Parameter | Values |
| --- | --- |
| `action` | `scan`, `arm`, `disarm`, `rate`, `send` |
| `bus` | `RS232`, `RS485`, `CAN` (required for `rate` and `send`) |
| `rate` | For `rate`: one of 1200–115200 (serial) or 125000/250000/500000/1000000 (CAN) |
| `encoding` | For `send`: `hex` or `text` (`text` not allowed for CAN) |
| `data` | For `send`: HEX pairs (`01 03 FF`) up to 64 bytes (8 for CAN), or 1–64 UTF-8 text bytes; maximum 256 characters of input |
| `id` | For CAN `send`: identifier in HEX without `0x`, up to `7FF` (standard) or `1FFFFFFF` (extended) |
| `extended`, `rtr` | `0`/`1`. RTR requires empty data and `dlc` 0–8 |
| `dlc` | 0–8, RTR only |

Responses are `text/plain`:

- `202 Richiesta accettata` — the command is queued for the acquisition task; the outcome appears as `message` in the next `/api/events` poll.
- `400` — invalid field (HEX syntax, unsupported rate, identifier out of range, RTR with data, empty serial payload).
- `403` — invalid boot token.
- `409` — conflicting state: scanning while armed, arming/sending during a scan, sending while disarmed, or another command in progress.

Behavioral guarantees: commands execute exactly once, never retry automatically, and sending requires a prior `arm`. `arm` puts CAN in normal mode (the node sends ACKs); `disarm` returns it to listen-only. CAN sends are single-shot, so a queued frame is not retransmitted and its queuing is not a delivery confirmation.
